# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

React and TypeScript with Vite, deployed as a static site to GitHub Pages.

## Users

The primary user is Saunak, reusing source components across personal projects. The public gallery must also be clear enough for outside developers to inspect, understand, and copy components.

## Product Purpose

Sunny Components is a source-first React component library and user-facing gallery. It provides modular, accessible interface building blocks that can be copied directly into personal projects without package publishing or registry infrastructure.

## Positioning

The library turns the distinct visual language shared by Simply Sunny and Silk-S1 into reusable React source, pairing a restrained technical identity with unusually clear component demonstrations and implementation guidance.

## Operating Context

Components are browsed in a public documentation gallery, previewed in representative states, and copied from the repository into React projects. The gallery is inspired structurally by the Supabase Design System while following Apple design principles for clarity, hierarchy, adaptability, and accessibility.

## Capabilities and Constraints

- Source-code library only; no npm publication in the first release.
- User-facing component gallery with live previews, variants, usage snippets, props guidance, and accessibility notes.
- Searchable navigation, responsive layouts, and light and dark themes.
- Initial scope covers foundations, actions, inputs, display, feedback, navigation, and overlays.
- Repository name is `sunny-components`.
- Deployment target is GitHub Pages.

## Brand Commitments

- Preserve the Simply Sunny and Silk-S1 character: dark grid, fine borders, technical typography, precise spacing, subdued motion, and quiet confidence.
- Do not copy Supabase or Apple brand assets; use them as structural and craft references.
- Keep the Sunny identity restrained and recognizable rather than generic or ornamental.

## Product Principles

1. Source should be understandable and portable before it is clever.
2. Every component demonstrates real states, not decorative mockups.
3. Accessibility and responsive behavior are part of the component contract.
4. The gallery should make finding, evaluating, and copying a component effortless.
5. Visual personality comes from disciplined typography, grid, proportion, and interaction—not excess decoration.

## Accessibility & Inclusion

Target WCAG 2.2 AA fundamentals, keyboard operation, visible focus, reduced-motion support, sufficient contrast, semantic markup, and touch targets appropriate for small screens.
